# ADR 0003 — Migrate hand-built `%`-format HTML strings to Jinja2 templates

- **Status:** Accepted (Phase 1 hardening shipped; Phase 3 migration planned)
- **Date:** 2026-08-01
- **Planned execution:** Phase 3 (templating overhaul)
- **Deciders:** Security audit findings; maintainability review
- **Related code:** `page_routes.py`, `social_routes.py`, `web_app.py`, `new_features_routes.py` (string-built pages), `templates/` (target)

## Context

The web UI is generated by **Python string constants formatted with the `%`
operator**, concatenated into page shells at request time. This pattern caused
three distinct classes of problems:

1. **Runtime crashes from malformed format strings.** The audit confirmed five
   sites that raise `ValueError`/`TypeError` when rendered:
   - `page_routes.py` — reading-calendar, analytics, admin/users (literal `%`
     in CSS/JS such as `width:100%` and `cutout:"65%"` parsed as format
     specifiers);
   - `page_routes.py` — books page (a `%`-formatted grid embedded inside
     another `%`-formatted shell re-applies `%` to already-formatted HTML);
   - `social_routes.py:151` — an **operator-precedence bug** where `%` binds
     tighter than `+`, so only the final literal was the format string
     (1 placeholder) while 2 args were supplied → `TypeError`.

2. **XSS surface.** No autoescaping exists for hand-built strings; every
   interpolated value must be manually escaped per site. The audit confirmed
   one unescaped attribute (`new_features_routes.py:914`, `suggestion_id` in an
   `onclick` attribute) and flagged the general pattern as unsafe-by-default.

3. **Unmaintainability.** ~5 route modules duplicate the same HTML fragments
   (avatar, book card, stat cards, nav) with subtle drift; template fragments
   live inside Python, so they cannot be linted, autoescaped, or reused.

## Decision

- **Phase 1 (already shipped): harden in place, do not redesign mid-security.**
  - Fix all five crash sites: `%%`-escape literal percent signs inside
    `%`-formatted templates, and switch the nested books-page shell from
    `%`-formatting to token `.replace()` (because the embedded grid legitimately
    contains literal `%` after its own formatting pass).
  - Fix the `social_routes.py:151` precedence bug by rewriting as a single
    format string with JS-safe escaping of the interpolated `book_id`.
  - Add regression tests: `tests/security/test_web_security.py::TestCrashSiteRoutes`
    asserts each affected route returns HTTP 200, with a favorite book seeded so
    the profile route exercises the favorites path.
- **Phase 3 (the actual migration): convert every hand-built HTML string page
  to a real Jinja2 template extending a base layout.**
  - Autoescaping stays **ON** everywhere; any deliberate `|safe` requires an
    inline comment justifying it.
  - Shared components become macros in `templates/macros.html` (book card,
    avatar, nav, stat card, notification item) — one source of truth instead of
    five duplicated copies.
  - Delete the dead `templates/landing.html` / string-landing duplication —
    exactly one implementation per page.
  - The XSS fixes from Phase 1 become structural: with autoescape, `suggestion_id`
    and every other interpolated value are escaped by default, and the remaining
    JS-in-attribute cases are handled by an explicit JS-safe filter/macro.
- Every migrated page gets a request test asserting HTTP 200 + no traceback,
  replacing the crash-site tests as the safety net moves from "fixed site" to
  "whole template".

## Consequences

### Positive

- Eliminates the crash class entirely: Jinja's `{{ }}` has no `%`-specifier
  semantics, so a literal `%` in CSS/JS cannot break rendering.
- Safe-by-default output: autoescaping closes the XSS class that the manual
  escaping pattern kept reintroducing.
- One canonical component per UI element; templates are lintable, testable, and
  editable without Python string-escaping gymnastics.
- Readability and onboarding: page markup lives in `.html` files, not inside
  `f"...".replace(...)` chains.

### Negative

- Large mechanical change surface (every route in the four modules), which is
  why it is sequenced as its own phase with the full suite + smoke-test
  checklist as the gate.
- The interim state (post-Phase-1) is still `%`-formatting; it is now correct
  and tested, but remains fragile — Phase 3 must not be skipped.

### Regression coverage

- Phase 1: `TestCrashSiteRoutes` (5 route-200 tests, favorites path included).
- Phase 3: one request test per migrated page; the Phase 0 smoke checklist
  re-run end-to-end after migration.

## Alternatives considered

- **Switch to f-strings.** Rejected: f-strings solve neither XSS (still manual
  escaping) nor reuse (still Python-embedded markup); they only fix `%`-crash
  bugs, which `%%` escaping already addressed.
- **Adopt a JS framework (React/Vue).** Rejected as disproportionate for
  server-rendered pages; Jinja2 matches Flask conventions, keeps the app
  server-rendered (SEO/portfolio simplicity), and the JS layer can be
  progressively enhanced later (Phase 3 frontend build).
